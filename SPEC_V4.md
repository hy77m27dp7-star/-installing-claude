Schema (0008_v4.sql, the `places` and `panel_cache` tables; the SQL is at the tail):

```
places (id TEXT PRIMARY KEY, thread_id TEXT UNIQUE, title TEXT NOT NULL, title_norm TEXT NOT NULL, detail TEXT, lat REAL, lon REAL, geocoded_by TEXT CHECK (geocoded_by IN ('owner','openmeteo','map')), picture_key TEXT, picture_sha256 TEXT, picture_bytes INTEGER, picture_light TEXT CHECK (picture_light IN ('day','night')), picture_season TEXT, picture_prompt TEXT, picture_provider TEXT, picture_model TEXT, picture_made_at TEXT, last_used_at TEXT, created_at TEXT NOT NULL, updated_at TEXT NOT NULL)
panel_cache (k TEXT PRIMARY KEY, json TEXT NOT NULL, fetched_at TEXT NOT NULL)
```

A place row shadows an active `life_threads` row of kind `place` (v2 section W). Threads are versioned (an edit is a new row id), so the join key is `title_norm` (the title lowercased, whitespace collapsed) and `thread_id` is the current head, refreshed by `syncPlaces` on every read: for each `title_norm` the newest active head (by `created_at`, then id) is the one that counts, so two active place threads sharing a title never fight over one row; a head whose `title_norm` matches an existing row updates that row's `thread_id` only when it differs (a read with nothing new writes nothing); an active place thread with no row gets one (`INSERT OR IGNORE`). Nothing in src/life.ts changes. A dropped thread keeps its places row (the picture was paid for) and the row is listed with `active: false`.
